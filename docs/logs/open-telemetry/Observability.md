## [Observability primer](https://opentelemetry.io/docs/concepts/observability-primer/)

---

### Observabilityとは

- 内部構造を知らなくてもシステムを外部から理解できる仕組み
  - 「なぜこの問題が起きているか」を問い、未知の問題（unknown unknowns）の調査・対処に役立つ
  - アプリケーションに適切な計測機能が備わっている必要がある（←シグナル）
    1. トレース
    2. ログ
    3. メトリクス
  - 問題調査の際に計装を追加しなくても必要な情報が得られる状態が、適切に計装された目安
- OpenTelemetry は、アプリケーションを計装してシステムを可観測にするための仕組み

### Reliability and metrics

- テレメトリ
  - システムから出力されるデータとその動作に関するデータのこと(データは、トレース、 メトリクス、 ログなどの形式)
- 信頼性
  - 「サービスがユーザーの期待どおりに機能しているか？」
    - ex) 【ユーザ】「カートに追加」を押下・【システム】カートへ追加しない　←アウト

- メトリクス
  - インフラまたはアプリケーションに関する数値データを一定期間にわたって集計したもの
    - ex) システムエラー率、CPU使用率、特定のサービスに対するリクエスト率

- SLI(Service Level Indicator)
  - サービスの動作を測定する指標(ユーザの視点から評価)
    - ex) ウェブページの読み込み速度

- SLO(Service Level Objective)
  - 1つ以上のSLIをビジネス価値に結び付け、組織や他チームに信頼性を伝える手段
    - (AI)SLI：正常に処理できたリクエストの割合・SLO：その割合を、直近30日間で 99.9%以上にする

### Understanding distributed tracing

- 分散トレーシング
  - ログ、スパン、トレースといった各構成要素からなる
- ログ
  - サービスやその他のコンポーネントによって送信されるタイムスタンプ付きのメッセージ

  ```plain text
  I, [2021-02-23T13:26:23.505892 #22473]  INFO -- : [6459ffe1-ea53-4044-aaa3-bf902868f730] Started GET "/" for ::1 at 2021-02-23 13:26:23 -0800
  ```

  - **ログはコードの実行状況を追跡するには不十分: 呼び出し元などのコンテキスト情報が欠けている**

- スパン
  - 単一の作業単位または操作で何が起こったかを把握できるようにする
    - 名前
    - 時間関連データ
    - 構造化ログメッセージ
    - その他メタデータ

  - スパン属性（Span attributes）はスパンに付与するメタデータ
    - HTTPリクエストの属性例: `http.request.method` (`GET`)、`url.path` (`/webshop/articles/4`)、`server.address`、`http.response.status_code` (`200`)
    - プロキシを経由する場合、`client.address`（クライアント）と`client.socket.address`（接続元ソケット）は異なる場合がある

- 分散トレース（Distributed trace）
  - アプリケーションまたはエンドユーザーの単一リクエストが、複数サービスを通過する経路を記録する
  - 1つ以上のスパンで構成される
    - 最初のスパンはルートスパン（root span）で、リクエスト全体を表す
    - 子スパンはリクエスト内の個々の処理を詳しく示す
  - ex) WebページのリクエストがAPI Gateway、バックエンド、データベースを通過する場合、各処理がスパンとなり、全体を1つのトレースとして追跡できる
  - 分散システムの健全性把握や、ローカルで再現しにくい問題のデバッグに役立つ

- ログとトレースの関連
  - ログは特定のユーザーリクエストやトランザクションに必ずしも関連付かない
  - スパンにログを含めるか、ログをトレースおよびスパンと関連付けると文脈が補われ、有用性が高まる
