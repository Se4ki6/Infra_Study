## [トレース | OpenTelemetry](https://opentelemetry.io/ja/docs/concepts/signals/traces/)

---

### トレース

- トレースは、リクエストがアプリケーション内を通る経路と、その間に何が起きたかを示す
  - モノリスからサービスメッシュまで、リクエスト全体を理解するのに役立つ
- トレースはスパンで構成される
  - 同じ `trace_id` を持つスパンが同一トレースに属する
  - `parent_id` がスパン間の親子関係を表す
  - 親を持たないスパンがルートスパンで、操作全体の開始と終了を示す
  - 子スパンは個別の作業を表し、兄弟スパンは同じ親を持つ
- スパンは構造化ログに似ており、コンテキスト・相関・階層を持つ
  - 異なるプロセス、サービス、仮想マシン、データセンターをまたいでエンドツーエンドの視点を提供する
- ページの JSON は概念説明用の表現であり、特定の形式や OTLP/JSON を示すものではない

### トレーサープロバイダー

- `TracerProvider` は `Tracer` のファクトリー
- 多くのアプリケーションでは一度初期化し、アプリケーションと同じライフサイクルで使う
  - 初期化にはリソースとエクスポーターの初期化も含まれる
  - 一部の言語 SDK ではグローバルなプロバイダーが既に初期化されている

### トレーサー

- トレーサーは、サービス内のリクエストなどの操作について詳細を含むスパンを作成する
- トレーサープロバイダーから作成される

### トレースエクスポーター

- トレースをコンシューマーへ送信する
  - 標準出力、OpenTelemetry Collector、オープンソースまたはベンダーのバックエンドなどが宛先となる

### コンテキスト伝搬

- コンテキスト伝搬は分散トレースの中心となる仕組み
- スパンの生成場所が異なっていても、相互に関連付けて一つのトレースに組み立てられる

### スパン

- スパンは作業または操作の単位であり、トレースの構成要素
- スパンには次の情報が含まれる
  - 名前
  - 親スパン ID（ルートスパンでは空）
  - 開始・終了タイムスタンプ
  - スパンコンテキスト、属性、イベント、リンク、ステータス
- 親スパン ID によってスパンを入れ子にでき、アプリケーション内の作業を詳しく表せる

#### スパンコンテキスト

- スパンコンテキストは各スパンに属する不変の情報
  - スパンが属するトレースの `TraceId`
  - `SpanId`
  - トレースフラグ（トレースに関する情報を含むバイナリ値）
  - ベンダー固有情報を保持するキーと値のペア
- 分散コンテキストや Baggage とともにシリアライズされ、伝搬される
- TraceId を含むため、スパンリンクの作成にも使われる

#### 属性

- 属性はスパンに操作のメタデータを付けるキーと値のペア
  - 例: ショッピングカートへの商品追加では、ユーザー ID、商品 ID、カート ID など
- スパン作成時または作成後に属性を追加できる
  - SDK のサンプリングで属性を使えるよう、可能ならスパン作成時に設定する
  - 後から値が必要になった場合はスパンを更新する
- 属性キーは NULL でない文字列
- 属性値は NULL でない文字列、ブール値、浮動小数点数、整数、またはそれらの配列
- 一般的な操作で共通するメタデータにはセマンティック属性の命名規則を使うと、システム間で意味を揃えやすい

#### スパンイベント

- スパンイベントはスパン上の構造化ログメッセージや注釈のようなもの
- スパンの期間中に起きた、意味のある特定時点を記録する
  - ページ読み込み全体は開始・終了を持つスパンで表す
  - ページが操作可能になった時点はスパンイベントで表せる

##### スパンイベントとスパン属性の使い分け

- データに結び付くタイムスタンプ自体に意味があるかを基準にする
  - 特定時点が重要ならスパンイベントに付ける
  - タイムスタンプが重要でなければスパン属性にする

#### スパンリンク

- スパンリンクは一つのスパンを他の一つ以上のスパンに関連付け、因果関係を示唆する
- 非同期処理など、親子関係として一つのトレースにまとめにくい処理のトレース同士を関連付けるのに使える
  - 例: 最初のトレースの最後のスパンを、後続処理を表す別トレースの最初のスパンにリンクする
- リンクは必須ではないが、関連するスパンを結び付ける方法となる

#### スパンステータス

- ステータスは `Unset`、`Error`、`Ok` のいずれか
- `Unset` がデフォルトで、エラーなしに操作が完了したことを表す
- `Error` は追跡対象の操作でエラーが発生したことを表す
  - 例: サーバーがリクエスト処理で HTTP 500 を返した
- `Ok` は開発者が明示的に成功と確定した状態
  - 通常、成功を明示設定する必要はなく、`Unset` で表せる

#### スパンの種類（SpanKind）

- `SpanKind` はトレースバックエンドがトレースを組み立てる際の手掛かり
- 種類を指定しない場合は `Internal` とみなされる
- サーバースパンはリモートクライアントスパンを親に持つことが多く、クライアントスパンの子は通常サーバースパン
- コンシューマースパンはプロデューサースパンの後続処理を表す

##### Client（クライアント）

- 発信する同期リモート呼び出しを表す
  - 例: HTTP リクエスト、データベース呼び出し
  - ここでの「同期」は `async/await` の有無ではなく、後で処理するためキューに入れられないことを指す

##### Server（サーバー）

- 同期的に着信するリモート呼び出しを表す
  - 例: HTTP リクエスト、リモートプロシージャコール

##### Internal（内部）

- プロセス境界を越えない操作を表す
  - 例: 関数呼び出し、Node.js の Express ミドルウェア

##### Producer（プロデューサー）

- 後で非同期に処理される可能性があるジョブの作成を表す
  - リモートのジョブキューに入れる処理や、イベントリスナーが処理するローカルジョブなど

##### Consumer（コンシューマー）

- プロデューサーが作成したジョブの処理を表す
  - プロデューサースパンが終了してから時間が経過した後に開始する場合もある
