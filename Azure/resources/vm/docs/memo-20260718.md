1. VM 作成画面 →「Basics」タブ →「Image」のドロップダウンで「See all images」をクリック
2. Marketplace 検索で Canonical → Ubuntu Server を選ぶと、右側のプレビューパネルに Offer/SKU 相当の情報が表示される
3. Portal の GUI では publisher/offer/sku を直接テキストで見せてくれないことが多いので、確実に値を確認したいときは Azure CLI が早い:

**network.bicep**
```bicep
// =============================================================================
// network.bicep
//   VNet / Subnet / NSG / Public IP / NIC をまとめて作成する最小ネットワーク。
//   VM モジュールに NIC ID を渡すことで疎結合に保つ。
// =============================================================================

@description('リソース名のプレフィックス（小文字正規化済みを推奨）')
param namePrefix string

@description('環境識別子（dev / stg / prod）')
param environment string

@description('デプロイ先リージョン')
param location string

@description('SSH を許可する送信元 IP/CIDR。0.0.0.0/32 は何も許可しないダミー値')
param allowedSshSourceAddressPrefix string

@description('共通タグ')
param tags object = {}

// ---- 命名（CAF 略語 + {prefix}-{env}） ----
var vnetName   = 'vnet-${namePrefix}-${environment}'
var subnetName = 'snet-default'
var nsgName    = 'nsg-${namePrefix}-${environment}'
var pipName    = 'pip-${namePrefix}-${environment}'
var nicName    = 'nic-${namePrefix}-${environment}'

// ---- アドレス空間（最小） ----
var vnetAddressPrefix   = '10.0.0.0/16'
var subnetAddressPrefix = '10.0.0.0/24'

// SSH(22/TCP) を allowedSshSourceAddressPrefix からのみ許可する NSG
// その他の受信は Azure 既定の DenyAllInbound に任せる（明示 Deny は書かない）
resource nsg 'Microsoft.Network/networkSecurityGroups@2024-07-01' = {
  name: nsgName
  location: location
  tags: tags
  properties: {
    securityRules: [
      {
        name: 'Allow-SSH-From-MyIP'
        properties: {
          description: 'SSH を指定送信元 IP のみ許可'
          priority: 1000
          direction: 'Inbound'
          access: 'Allow'
          protocol: 'Tcp'
          sourceAddressPrefix: allowedSshSourceAddressPrefix
          sourcePortRange: '*'
          destinationAddressPrefix: '*'
          destinationPortRange: '22'
        }
      }
    ]
  }
}

// VM を配置するためのプライベートネットワーク本体
resource vnet 'Microsoft.Network/virtualNetworks@2024-07-01' = {
  name: vnetName
  location: location
  tags: tags
  properties: {
    addressSpace: {
      addressPrefixes: [
        vnetAddressPrefix
      ]
    }
  }
}

// VNet 内のセグメント。NIC をここに配置し、NSG をサブネットに紐付ける
resource subnet 'Microsoft.Network/virtualNetworks/subnets@2024-07-01' = {
  parent: vnet
  name: subnetName
  properties: {
    addressPrefix: subnetAddressPrefix
    networkSecurityGroup: {
      id: nsg.id
    }
  }
}

// VM への外部到達点。Standard SKU + Static（Basic SKU は 2025-09-30 でリタイア済）
resource publicIp 'Microsoft.Network/publicIPAddresses@2024-07-01' = {
  name: pipName
  location: location
  tags: tags
  sku: {
    name: 'Standard'
    tier: 'Regional'
  }
  properties: {
    publicIPAllocationMethod: 'Static'
    publicIPAddressVersion: 'IPv4'
  }
}

// VM と VNet/Public IP を接続する NIC（NSG はサブネット側に付与）
resource nic 'Microsoft.Network/networkInterfaces@2024-07-01' = {
  name: nicName
  location: location
  tags: tags
  properties: {
    ipConfigurations: [
      {
        name: 'ipconfig1'
        properties: {
          privateIPAllocationMethod: 'Dynamic'
          subnet: {
            id: subnet.id
          }
          publicIPAddress: {
            id: publicIp.id
          }
        }
      }
    ]
  }
}

// ---- 出力（後続モジュール / 接続情報） ----
@description('VM モジュールに渡す NIC リソース ID')
output nicId string = nic.id

@description('SSH 接続先の Public IP アドレス（Static なので作成時点で確定）')
// 注: Static でも作成直後 / what-if の段階では空文字列で返ることがある（既知の ARM 応答挙動）。
//      実際の IP は `az network public-ip show -g <rg> -n <pipName>` で再確認する。
output publicIpAddress string = publicIp.properties.ipAddress
```

network.bicep で作られる5つのリソース（NSG / VNet / Subnet / Public IP / NIC）は、それぞれ独立したPortalブレードを持つものと、親リソースの中でしか見えないものが混在しているらしい

- NSG
> 何のリソースか：受信/送信トラフィックのフィルタルールの集合。今回は「SSHを指定IPからのみ許可」という1本のルールだけを持つ。
  - Portal検索バーで「ネットワークセキュリティグループ」→ 一覧から nsg-{prefix}-{env}
  - ブレード内 設定 > 受信セキュリティ規則：Allow-SSH-From-MyIP の優先度(1000)・プロトコル(TCP)・送信元・ポート(22)がテーブルで見える
  - 設定 > 有効なセキュリティ規則（Effective security rules）：NSGブレード単体には無く、後述のNICブレードから見る必要がある点に注意

65500:DenyAllInBoundがデフォルトでそれより数値が低ければAllowになりそう

- VNet
> 何のリソースか：VMを配置するプライベートネットワークの箱そのもの（10.0.0.0/16）。
  - Portal検索バーで「仮想ネットワーク」→ vnet-{prefix}-{env}
  - 概要タブでアドレス空間を確認、または 設定 > アドレス空間 ブレードで編集可能な形で確認
  - 設定 > サブネット ブレードに snet-default が一覧表示される（ここがSubnetの入口）

- Subnet
  - VNetブレード → 設定 > サブネット → snet-default をクリックすると詳細画面
  - ここでアドレス範囲(10.0.0.0/24)、そして重要な**「ネットワークセキュリティグループ」欄**に nsg-{prefix}-{env} が紐付いていることが確認できる
    - Bicepコメントの「NSGはサブネット側に付与」を裏付ける画面がここ

- PublicIP
> 何のリソースか：VMへの外部到達点。Standard SKU + Static。
  - Portal検索バーで「パブリックIPアドレス」→ pip-{prefix}-{env}
  -  概要タブでIPアドレスの値、割り当て方法（静的）、SKU（Standard）を確認
  -  Bicepのコメントにある「作成直後は空文字列で返ることがある」はARMのデプロイ出力（what-if/output）の話で、Portal上の値自体はデプロイ完了後なら通常表示されている。もし空に見えたらブレードの更新ボタンを押すか az network public-ip show -g <rg> -n <pipName> --query ipAddress で確認

- NIC(ここに一番情報が集まる)
> 何のリソースか：VMとVNet/Public IPを繋ぐ接続点。
  - Portal検索バーで「ネットワークインターフェイス」→ nic-{prefix}-{env}
  - 概要タブ：紐づくVM名、プライベートIP、パブリックIP、VNet/サブネットが要約表示
  - 設定 > IP構成：ipconfig1 の詳細（動的割り当て、どのサブネットか、どのPublic IPと紐付いているか）
  - 設定 > ネットワークセキュリティグループ：NIC自体にはNSGを付けていないので「サブネットのNSGが適用されている」旨の表示になるはず
  - 設定 > 有効なセキュリティ規則（Effective security rules）：★ここが一番実用的。サブネットNSG + NIC NSG（今回は無し）+ Azure既定ルールをすべて合成した「実際に効いているルール一覧」が出る。「本当にSSHだけ通るか」を確認したいときはここを見るのが一番早い
