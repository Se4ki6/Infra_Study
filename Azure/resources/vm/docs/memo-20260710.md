## つまずき① VMサイズがどこも在庫切れ / クォータ0

japaneast に変えても what-if で同じエラーが出た。

```
SkuNotAvailable - Following SKUs have failed for Capacity Restrictions: Standard_B1s
  is currently not available in location 'japaneast'.
```

### ポイント: `--location` と paramの `location` は別物
- `--location japaneast` … デプロイの**メタ情報の置き場所**（VMの場所ではない）
- `main.bicepparam` の `param location` … **実際にVMが建つ場所**
- VMの容量チェックは後者で走るので、paramを japaneast にしたことでエラーが japaneast 基準になった

### 切り分け結果（2つの別々の壁）

| SKU | ファミリ | エラー | 意味 |
|---|---|---|---|
| B1s / B1ls | standardBSFamily | `SkuNotAvailable` | クォータはあるが**物理在庫が今ゼロ**（日本・US含め全滅） |
| B2ats_v2 | standardBasv2Family | `QuotaExceeded`（Limit:0） | このサブスクは**このファミリの枠が0**。増額申請が要る |

`az vm list-usage` で確認したら **Total Regional vCPUs は Limit 10**（コア枠は足りている）。
→ 原因は「コア数」ではなく「ファミリごとの在庫/クォータ」だった。

### 対処: what-if を使って「通るサイズ」を総当たり
what-if 自体が preflight（容量/クォータ）チェックを兼ねるので、これで無害に探せる。
japaneast で通ったのは **`Standard_D2as_v4`** と **`Standard_D2s_v3`** の2つだけ。コスト重視で D2as_v4 を採用。

→ `main.bicep` / `virtual_machine.bicep` の `@allowed` をこの2つに整理、`main.bicepparam` の `vmSize` を `Standard_D2as_v4` に確定。

> 学び: **このサブスク(`sekishiro-learn`)ではB系は使えない。最初からD2as_v4で計画する。**

## つまずき② ファイルを移動してパスが変わった

`VM\infra-bicep\` → `resources\vm\infra-bicep\`（さらに `resource-learn\vm\` 等に整理）へ移動したため、
古いパスを指す what-if が `Could not find ... main.bicepparam` で失敗した。

→ コマンドのパスを新しい場所に直せば解決。`.bicepparam` の `using './main.bicep'` は**相対パスなので、bicepparamと同じフォルダにmain.bicepがあれば自動で解決**される。

---

## つまずき③ ペーストで変数がセットされず、ダミー値のままデプロイしそうになった

`$sshSource` を別行で代入 → 次の行で使う、という書き方だと、
**ペースト時に改行が崩れて変数代入が実行されず**、NSGのSSH許可元が `0.0.0.0/32`（ダミー）のままになっていた。

```
properties.sourceAddressPrefix: "0.0.0.0/32"   ← これだと誰もSSHできない箱になる
```

### 対処: 変数を使わず、1本のコマンドにインライン展開
```pwsh
az deployment sub what-if --location japaneast --parameters resources\vm\infra-bicep\main.bicepparam --parameters sshPublicKey="$((Get-Content $HOME\.ssh\id_ed25519.pub -Raw).Trim())" allowedSshSourceAddressPrefix="$(Invoke-RestMethod https://api.ipify.org)/32"
```
これで what-if の NSG が実IP `160.237.73.239/32` になり、合格。

> what-ifの確認の勘所: **NSGの `sourceAddressPrefix` が自分の実IPになっているか**。`0.0.0.0/32` なら注入失敗。

## デプロイ

```pwsh
az deployment sub create --name vm-dev-initial --location japaneast --parameters resources\vm\infra-bicep\main.bicepparam --parameters sshPublicKey="$((Get-Content $HOME\.ssh\id_ed25519.pub -Raw).Trim())" allowedSshSourceAddressPrefix="$(Invoke-RestMethod https://api.ipify.org)/32"
```

- `provisioningState: Succeeded`（約1分15秒）
- 出力: `publicIpAddress = 20.48.89.165`, `vmName = vm-vm-dev`, `resourceGroupName = rg-vm-dev`
- 作成された8リソース: RG / VNet / Subnet / NSG / Public IP / NIC / VM / Auto-Shutdownスケジュール

## メモ（Q&A・気づき）

### Q. ポータルに `NetworkWatcher_japaneast`（別RG `NetworkWatcherRG`）が勝手に増えてる？
Bicepが作ったものではない。**Azureが、あるリージョンで初めてネットワーク系リソースを作ると自動でNetwork Watcher(通信診断)を用意する**仕様。課金はほぼ無し。`rg-vm-dev` を消しても別RGなので残る（放置でOK）。

### Q. サブネットが一覧に単独で出ない
サブネットはVNetの子リソース。`vnet-vm-dev` を開いた中に含まれる（正常）。

### ⚠️ 終了時の最重要ポイント: `exit` では課金は止まらない
| やること | コマンド | 課金 |
|---|---|---|
| SSHを抜けるだけ | `exit` | **課金継続**（VMは起動したまま） |
| VMを停止（推奨） | `az vm deallocate -g rg-vm-dev -n vm-vm-dev` | 計算課金停止（ディスク少額のみ残る） |
| 全部消す | `az group delete -n rg-vm-dev` | ほぼゼロ |

今夜22:00にAuto-Shutdownで自動停止するが、今日もう使わないなら手動で `deallocate` するのが安全。

### 画像共有に使った公開Blobについて
このメモ用のスクショ共有に、別で作った公開Blob(`stpublicdevuhmtgr` / コンテナ `public-assets`)を使った。
`allowBlobPublicAccess: true` + コンテナ `publicAccess: 'Blob'` で**URLを知っていれば誰でも匿名で読める**（一覧は不可）。公開素材専用の割り切り運用。秘密の画像は置かない。
URLにスペースや日本語が入ると `%20` エンコードが要るので、共有用途はASCII・ハイフン区切りのファイル名が楽。
