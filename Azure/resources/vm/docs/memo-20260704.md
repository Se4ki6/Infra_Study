## メモ

### Q. サブスクリプションとは？
サブスクリプション = 「課金と管理の境界となる入れ物」
ひとことで言うと、Azureリソースをまとめる“課金単位＋管理単位”のコンテナです。作ったリソースの料金は、すべてそれが属するサブスクリプションに集計され、そこに紐づく支払い方法に請求されます。

Azureの階層構造の中での位置
Azureは4段の入れ子になっていて、サブスクリプションは上から3番目です。

```markdown
[1] Microsoft Entra ID テナント   ← 組織/アカウントの認証の傘（誰がログインできるか）
      └ [2] Management Group      ← サブスクリプションを束ねる（任意・大規模組織向け）
            └ [3] Subscription    ← ★これ。課金と権限とクォータの境界
                  └ [4] Resource Group  ← リソースをまとめるフォルダ
                        └ リソース（VM, VNet, Storage ...）
```
今回のVM構成で言うと:
```markdown
Subscription（請求先）
  └ rg-vm-dev（Resource Group）
       └ VM / VNet / NSG / Public IP ...
```
サブスクリプションは単なる区切りではなく、次の4つの境界を同時に引きます。

境界	意味
課金	料金はサブスク単位で集計・請求される。プロジェクト別/部署別に分けることが多い
権限(RBAC)	「このサブスクの共同作成者」のようにアクセス権をまとめて付与できる
クォータ(上限)	「このリージョンでvCPU合計○個まで」等の上限がサブスク単位で決まる
ポリシー	Azure Policy でサブスク全体に規則を強制できる（例: このリージョン以外禁止）

### Q. `ssh-keygen -t ed25519 -f $HOME\.ssh\id_ed25519` のコマンドの意味は？
ssh-keygen -t ed25519 -f $HOME\.ssh\id_ed25519
「Ed25519方式の鍵ペアを1組作り、~/.ssh/id_ed25519 という名前で保存する」 コマンドです。

分解
要素	意味
ssh-keygen	SSH鍵ペアを生成するツール（Windows 11のOpenSSHに標準同梱）
-t ed25519	鍵の種類(type) を指定。ed25519 という楕円曲線暗号方式
-f $HOME\.ssh\id_ed25519	出力ファイル(file) のパスと名前。$HOMEはあなたのユーザーフォルダ
-t ed25519 とは（鍵の種類）
鍵の暗号アルゴリズムの選択です。主な候補:

種類	特徴
ed25519 ← 推奨	新しい楕円曲線方式。短い鍵で高強度・高速。今のデファクト
rsa	古くからの定番。互換性は高いが、同強度だと鍵が長い（-b 4096推奨）
ecdsa / dsa	非推奨・旧式（dsaは実質廃止）
特別な理由がなければ ed25519一択です。Azure VMもこれで問題なく認証できます。

-f が作る「2つのファイル」（最重要ポイント）
ssh-keygen は必ず鍵ペア＝2ファイルを吐きます。


$HOME\.ssh\id_ed25519       ← 秘密鍵 (private key)  ★絶対に他人に渡さない・PCから出さない
$HOME\.ssh\id_ed25519.pub   ← 公開鍵 (public key)   ★これはサーバーに配ってよい
秘密鍵 = あなたの手元に置く「本人の証明」。これが漏れると誰でもログインできてしまう。
公開鍵 = 錠前側。サーバー（VM）に置いておき、「この錠前を開けられる秘密鍵を持つ人だけ入れる」という仕組み。
今回のBicepで言うと、.pub（公開鍵）の中身を sshPublicKey パラメータでVMに埋め込み、ログイン時にあなたの手元の秘密鍵と照合してSSH接続します。だから what-if / デプロイでは:


$sshPublicKey = Get-Content $HOME\.ssh\id_ed25519.pub -Raw   # ← .pub の方を読む
と、公開鍵(.pub)だけを渡します。秘密鍵は絶対に渡しません。

### Q. what-ifの下記コマンドの意味は？
```pwsh
az deployment sub what-if `
    --location eastus `
    --parameters VM\infra-bicep\main.bicepparam `
    --parameters sshPublicKey="$sshPublicKey" allowedSshSourceAddressPrefix="$sshSource"
```

部分	意味
az deployment sub what-if	「デプロイの**予測(what-if)**を、subscriptionスコープで実行せよ」。subなのはRG作成から始めるため（RGはサブスク直下にできる）
` （各行末）	PowerShellの行継続。「1つの長いコマンドが次の行に続く」という意味。改行して見やすくしているだけ
--location eastus	subスコープのデプロイは“入れ物”のRGがまだ無いので、デプロイのメタ情報を置くリージョンを指定する必要がある（VM自体の場所はparamで別途決まる）
--parameters VM\infra-bicep\main.bicepparam	パラメータを bicepparamファイルから読む。このファイルの using './main.bicep' からテンプレート本体も自動で特定される（だから--template-fileが不要）
--parameters sshPublicKey="..." allowedSshSourceAddressPrefix="..."	paramファイルのダミー値を実値で上書き。公開鍵と、SSH許可元IP。後勝ちで上書きされる
なぜ --parameters が2回あるのか（重要ポイント）
1回目: ファイルから“土台”のパラメータを一括で読み込む
2回目: そのうち機微な2項目だけを実値で差し替える
paramファイルには鍵とIPをダミー(REPLACE_ME... / 0.0.0.0/32)で置いてあり、本物はGit管理下に置かず実行時にCLIで注入するという設計です（main.bicepparam の16-22行のコメント通り）。$sshPublicKey と $sshSource は、さっきあなたが変数に入れた値がここに展開されます。
